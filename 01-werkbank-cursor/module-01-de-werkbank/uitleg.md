# Uitleg — waarom zélf draaien?

Het waaróm achter deze eerste module. Kort, maar het legt de basis voor alles wat komt.

---

## Een `.py`-bestand is gewoon tekst

`opdracht.py` is een tekstbestand. De `.py`-uitgang vertelt de computer: "dit is
**Python**-code." Meer is het niet. Je kunt het openen, lezen en aanpassen zoals elke
tekst. Pas als je het *draait*, leest Python de regels van boven naar beneden en voert
ze uit.

---

## Editor vs. terminal — twee verschillende dingen

Dit verwarren beginners het vaakst:

- De **editor** is waar je code *schrijft en leest*. Iets veranderen in de editor doet
  op zichzelf nog niets.
- De **terminal** is waar je code *laat draaien* en het **resultaat** ziet. `print(...)`
  zet tekst in de terminal.

Vergelijk het met een recept: de editor is het receptenblad, de terminal is de keuken
waar je het gerecht daadwerkelijk maakt.

---

## De feedback-loop: veranderen → draaien → kijken

De belangrijkste gewoonte die je hier oefent is een **lus**:

1. verander iets kleins,
2. draai het bestand,
3. kijk of het resultaat is wat je verwachtte.

Deze lus is straks je belangrijkste gereedschap. Ook wanneer een AI de code schrijft,
blijf jíj degene die draait en controleert of het klopt. "Zien wat de code doet"
begint letterlijk bij op Enter drukken en kijken wat er gebeurt.

---

## Waarom dit vóór Python komt

Als draaien en kijken vanzelf gaan, kun je je in Fase 1 volledig op het *denken*
richten. Je verspilt geen energie meer aan "hoe krijg ik dit aan de praat". De
werkbank moet onzichtbaar worden, zodat het gereedschap alle aandacht krijgt.
